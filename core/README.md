# Warranty Core API (`warranty-core`)

> **High-Performance REST API Gateway and Business Dispatch Engine for UIT CARE Warranty Management.**  
> Built with **NestJS 11**, **Fastify**, **TypeORM**, and **Microsoft SQL Server 2022**.

---

## 1. Overview & Architecture

The `core` service acts as the central business orchestrator, security guard, and integration layer between the CRM frontend and the MSSQL database engine.

### Architectural Principles:
1. **Strict 3-Tier Layering**: `Controller` (HTTP routing, OpenAPI decorators, RBAC guards) ➔ `Service` (Business coordination & validation) ➔ `TypeORM Entity / Stored Procedure Proxy` (Data persistence).
2. **Database-Driven Financial Integrity**: Works in tandem with SQL Server triggers and stored procedures to guarantee immutable financial states.
3. **Fail-Fast Validation**: All request bodies and query parameters are validated via `class-validator` DTOs with `forbidNonWhitelisted: true`.
4. **Zero Relative Path Mess**: All internal imports use the `@/*` path alias mapped to `src/*`, resolved via TypeScript and `tsc-alias`.

## 2. Domain Modules

| Module | Description | Key Endpoints |
| :--- | :--- | :--- |
| **`auth`** | Dual-mode authentication (Bearer Header + HttpOnly Cookie), bcrypt password & refresh token hashing. | `POST /auth/login`<br/>`POST /auth/refresh`<br/>`POST /auth/logout`<br/>`GET /auth/me` |
| **`tickets`** | Service intake workflow, diagnostic updates, technician assignment, status transition enforcement. | `POST /tickets`<br/>`GET /tickets`<br/>`GET /tickets/:id`<br/>`PATCH /tickets/:id/status` |
| **`invoices`** | Billing management, labor & parts breakdown, automatic warranty discount, atomic checkout. | `POST /invoices`<br/>`GET /invoices/:id`<br/>`POST /invoices/:id/parts`<br/>`POST /invoices/:id/checkout` |
| **`customers`** | Customer records management with indexed phone number lookup. | `GET /customers`<br/>`POST /customers`<br/>`GET /customers/:id` |
| **`devices`** | Hardware catalog, serial number uniqueness, and warranty coverage status. | `GET /devices`<br/>`POST /devices`<br/>`GET /devices/:id` |
| **`parts`** | Inventory catalog, unit pricing, real-time stock levels, and restocking. | `GET /parts`<br/>`POST /parts`<br/>`PATCH /parts/:id/stock` |
| **`employees`** | Staff administration, role provisioning (`manager`, `receptionist`, `technician`). | `GET /employees`<br/>`POST /employees`<br/>`PATCH /employees/:id` |
| **`reports`** | Executive KPI dashboard, SLA delayed ticket monitoring, cursor-based financial audit. | `GET /reports/dashboard`<br/>`GET /reports/delayed-tickets`<br/>`POST /reports/audit-invoices` |

## 3. Global Filters, Guards & Error Handling

### Database Error Mapping (`AllExceptionsFilter`)
Custom T-SQL errors generated by SQL Server triggers and stored procedures are caught globally and mapped to standardized HTTP responses:

| T-SQL Code | Trigger / Procedure | HTTP Status | Description |
| :--- | :--- | :--- | :--- |
| **`50001`** | `trg_invoice_items_stock` | `400 Bad Request` | Insufficient stock for requested replacement part |
| **`50002`** | `sp_receive_device` | `409 Conflict` | Device already has an active, unfinished ticket |
| **`50003`** | `trg_tickets_workflow_guard` | `422 Unprocessable` | Repair status requires an assigned technician |
| **`50004`** | `trg_tickets_workflow_guard` | `422 Unprocessable` | Cannot deliver unfinished ticket or modify delivered ticket |
| **`50035`** | `trg_invoice_items_freeze_paid` | `422 Unprocessable` | Invoice is paid; part items are locked and immutable |
| **`50036`** | `trg_invoices_freeze_paid_amounts` | `422 Unprocessable` | Invoice is paid; financial amounts cannot be altered |

## 4. Environment Configuration

Copy the example configuration file:
```bash
cp .env.example .env
```

| Variable | Default Value | Description |
| :--- | :--- | :--- |
| `PORT` | `5001` | HTTP port for Fastify server |
| `NODE_ENV` | `development` | Runtime environment (`development` / `production`) |
| `DB_HOST` | `localhost` (or `database` in Docker) | Microsoft SQL Server host |
| `DB_PORT` | `1433` | Microsoft SQL Server port |
| `DB_USERNAME` | `sa` | Database user |
| `DB_PASSWORD` | `Warranty@Pass123` | Database password |
| `DB_DATABASE` | `warranty_management` | Database name |
| `JWT_SECRET` | `super_secret_jwt_key_...` | Symmetric key for signing JWT tokens |
| `JWT_EXPIRES_IN` | `7d` | Token expiration duration |

## 5. Development & Testing Scripts

```bash
# Install dependencies
pnpm install

# Start local server with hot-reload
pnpm run start:dev

# Run all unit tests with Jest
pnpm test

# Run tests in watch mode
pnpm run test:watch

# Check test coverage
pnpm run test:cov

# Production build with alias resolution
pnpm run build

# Start production server
pnpm run start:prod
```
